# 백엔드 진단·센서 리팩토링

기준 커밋: `b846f78c1366ec70c267d17c88c8cc4981d83a7b`.

## 결과 생성과 조회

센서 업로드는 측정값과 진단 요청을 같은 짧은 트랜잭션에 저장한다. 작업자가 커밋된
진단 요청을 선점하고, 데이터 조회 → 트랜잭션 밖의 Python AI 호출 → 결과 저장 순서로
처리한다. 프로세스가 중단되면 임대가 만료된 작업을 다른 작업자가 다시 처리할 수 있다.
재시도는 3회로 제한하고 실패한 작업에는 재요청 대기 시간을 둔다.

`GET /api/v1/care/products/{productId}/summary`는 외부 AI를 호출하지 않는다.
제품·분석 기간·센서 버전·원본 행 수가 맞고 5분 이내인 저장 결과를 사용한다. 없으면
해당 기간의 진단을 예약하고 공통 규칙의 임시 결과를 반환한다. 같은 진행 중 작업은
병합한다. 7D, 30D, 1Y는 각각 별도 결과이며 홈·대시보드·케어 제안은 30D를 사용한다.
원본 행 수와 AI가 판단한 유효 측정 수를 분리해 부분적으로 유효한 데이터도 캐시를
계속 무효화하지 않도록 했다.

문구 생성은 Python AI 서비스가 담당한다. Java의 직접 OpenAI 호출은 제거했다.
기존 `/api/v1/care/openai-status`는 호환성을 위해 남기되 Java 직접 호출의 `enabled`를
항상 false로 반환한다. 이 응답의 로컬 키 설정 여부는 Python의 키 상태를 의미하지 않는다.
Python 경로는 기존 `MXIS_AI_SERVICE_ENABLED`, `MXIS_AI_SERVICE_BASE_URL`,
`MXIS_AI_INTERNAL_API_KEY`, `MXIS_USE_OPENAI`, `OPENAI_MODEL` 설정을 사용한다.
HTTP 클라이언트를 재사용하고 연결 제한 시간 기본값 5초, 전체 요청 제한 시간 기본값
45초를 적용한다. `mxis.ai.service.connect-timeout-seconds`로 연결 제한을 조절할 수 있다.

## 판정과 API 변경

- 실제 AI 점수, 데이터 상태, 분석 기간, 케어 판단을 DB에 저장한다. 홈에서 등급을 임의
  점수로 다시 환산하지 않는다.
- `CareDecisionPolicy`가 폴백 점수·상태·제안 필요도·케어 주기를 함께 결정한다.
  폴백 점수는 STABLE 100, BALANCED 75, LIGHT_CARE 50, EXPERT_CHECK 25다.
  충분한 데이터에서 습도 75%, 온도 20℃, 충격 0회는 리포트와 요약 모두 LIGHT_CARE에
  해당하는 결과(50점, Needs Attention)를 사용한다.
- 온도와 습도가 모두 유효한 측정 24개 및 24시간 범위가 필요하다. 값이 모두 없는 행을
  추가해 정상 점수를 만들 수 없다. 3일 이상 지난 측정만 있으면 STALE_DATA다.
- 데이터가 부족하거나 오래됐으면 점수는 null, 공개 라벨은 Collecting Data다. 기존
  등급 API에는 `COLLECTING_DATA`가 추가된다. 케어 화면의 주기는 0, 다음 권장일은 null이다.
- MEDIUM 이상은 공통 정책에 따라 제안을 생성한다. 정상 회복·데이터 부족이면 기존
  제안을 해제한다. 같은 등급·케어 필요도·점검 필요도이면 기존 유효 제안의 ID와 일정은
  유지하며, 조회나 재시도 때문에 같은 알림을 다시 생성하지 않는다.
- 날짜 없는 값은 기존 API처럼 서울 현지 시각으로 해석한다. AI 응답의 UTC/offset 날짜는
  서울 시각으로 변환하며 센서·연결 시각과 DB 감사 시각에도 같은 Clock을 적용한다.
- 환경 그래프와 해당 화면의 평균·외출 수는 동일한 시작/종료 시각을 쓴다. 그래프의
  날짜/월 버킷은 유지하고 실제 조회 상한은 현재 시각으로 제한한다.

AI 응답 검증은 필수 객체, 상태·등급, 점수 범위, 충분성 최소 조건, 요청 분석 기간,
명시된 제품 ID를 확인한다. 잘못된 응답은 정상 결과로 보정하지 않고 폴백 저장 및
제한된 재시도 대상으로 처리한다. 원문 JSON과 서버 입력 메타데이터는 결과 추적에 남긴다.

## DB 변경과 적용

V15는 저장된 AI JSON에서 실제 상태·점수·케어 결정을 복원하고 분석 기간을 보정한다.
검증 가능한 점수가 없는 과거 결과는 수집 중 상태로 표시한다. 기존 폴백 등급에서 실제
AI 점수를 추측해 만들지 않는다. 조회 후 새 진단 결과로 갱신된다.

V16은 기기당 활성 제품 연결 하나를 DB에서 강제하고 영속 진단 작업 테이블을 추가한다.
기존 DB에 중복 활성 연결이 있으면 제약 추가가 실패하므로 적용 전에 다음 결과를 확인하고
실제 연결 상태에 맞게 정리해야 한다. 이 작업에서 운영 DB나 과거 측정 이력을 변경하지 않았다.

```sql
SELECT device_id, COUNT(*) AS active_links
FROM product_devices
WHERE detached_at IS NULL
GROUP BY device_id
HAVING COUNT(*) > 1;
```

새 스키마와 `COLLECTING_DATA` 응답을 함께 사용하는 변경이므로 구버전 서버와의 혼합 운영은
피하고, 프론트가 수집 중 상태·null 점수·null 권장일을 처리하는지 확인한 뒤 적용한다.
과거에 잘못 귀속된 측정값의 제품은 근거 없이 자동 수정하지 않는다.
