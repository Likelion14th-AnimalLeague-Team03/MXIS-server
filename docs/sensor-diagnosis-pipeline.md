# 센서 저장과 진단 작업

센서 배치 API의 201 응답은 측정값과 진단 작업의 저장이 완료됐음을 뜻한다. AI 호출은 요청 트랜잭션에 포함되지 않는다. 새 진단이 처리될 때까지 조회는 기존 스냅샷 또는 동일한 판정 정책의 임시 결과를 반환한다.

## 입력과 연결 이력

- 배치 최대 1000개. 같은 기기·순번·내용은 한 번만 저장하며, 같은 순번에 다른 내용은 409로 배치 전체를 거절한다. `receivedCount = savedCount + duplicateCount`가 항상 성립한다.
- 수치는 DB 정밀도를 넘으면 400으로 거절한다. 습도는 0~100%, 온도는 -273.15℃ 이상, 충격은 0 이상이어야 한다. 20과 20.00은 같은 값이다. 측정 시각은 Asia/Seoul 기준이며 마이크로초로 정규화한다.
- 환경 데이터 충분성과 평균·건조 비율·그래프는 온도와 습도가 모두 있고 위 범위를 만족하는 행으로 계산한다. 빈 측정 행은 정상 판정을 위한 표본으로 세지 않는다. 원본 행 수와 최신 ID는 별도로 보존해 새 입력의 캐시 무효화에 사용하며 충격은 환경값의 유무와 별도로 집계한다.
- 측정값은 `[attachedAt, detachedAt)` 연결 이력으로 귀속한다. 현재 연결이 없어도 유효한 과거 연결로 업로드할 수 있다. 연결 공백·중첩·다른 소유자의 제품·삭제된 제품에 대한 신규 측정은 409다.
- 기기 재등록은 센서 순번의 새 공간을 만들지 않는다. 펌웨어가 순번을 초기화할 경우 기존 순번과 다른 기록은 거절되므로, 순번 유지 또는 별도 프로토콜 버전이 필요하다.
- 연결·해제·삭제·기기 재등록·상태 갱신·센서 저장은 소유자 행 → 기기 행 순서로 잠근다. 여러 기기는 ID 순서로 잠근다. 사용자 단위 직렬화는 짧은 DB 작업에만 적용한다. 진단 결과 저장도 소유자 → 제품 순서를 따른다.
- V16의 `uq_active_product_device`는 기기당 활성 제품 연결 하나를 DB에서 보장한다. 기존 중복 이력은 자동으로 선택하거나 삭제하지 않으며 배포 전에 검토해야 한다.

## 영속 작업과 재시도

`care_diagnosis_jobs`는 제품·기간(7D/30D/1Y)별 최대 한 행을 유지한다. 새 센서 입력은 기본 30D 작업과 이미 요청된 다른 기간의 작업을 갱신한다. 조회가 같은 작업을 반복 요청해도 진행 중인 작업을 중복 생성하지 않는다.

1. 센서와 작업을 같은 트랜잭션에서 저장한다.
2. 작업자는 짧은 별도 READ_COMMITTED 트랜잭션의 원자적 조건부 갱신으로 작업 하나를 선점한다. 만료 작업 검색의 범위 잠금이 동시 선점과 교착하지 않게 하며, 일시적 DB 경합은 롤백 완료 후 다음 실행에서 다시 시도한다. 트랜잭션 종료 뒤 AI 호출을 실행한다.
3. 결과 저장은 제품 잠금과 센서 revision·분석 기간 비교로 오래된 결과를 거절한다. 완료·실패 갱신은 선점 토큰이 같은 경우에만 적용된다.
4. 처리 중 새 센서 데이터가 들어오면 요청 세대가 증가한다. 현재 작업 완료 후 새 세대가 다시 PENDING이 된다.
5. 실패는 최대 3회까지 시도한다. 1·2회 실패 후 30·60초를 기다리고, 3회 실패 시 FAILED로 둔다. 조회를 통한 재요청은 15분 후 가능하며 새 센서 입력은 새 세대로 바로 재요청한다.
6. 프로세스 종료로 RUNNING이 남으면 임대 만료 후 다른 인스턴스가 재선점한다. 최종 시도 중 종료된 작업도 FAILED 또는 신규 세대의 PENDING으로 복구한다.

애플리케이션 인스턴스마다 별도 스케줄러 스레드 하나가 한 번에 작업 하나만 실행한다. 예약 리마인더용 스케줄러와 분리되며 메모리의 무제한 작업 큐를 사용하지 않는다. 요청별 행이 계속 늘어나지 않는다.

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| `mxis.care.jobs.poll-delay-ms` | 1000 | 작업 완료 뒤 다음 선점까지 대기 |
| `mxis.care.jobs.initial-delay-ms` | 5000 | 서버 시작 뒤 최초 실행 지연 |
| `mxis.care.jobs.lease-seconds` | 300 | 실행권 임대 시간. AI 전체 제한시간과 결과 저장 시간보다 여유 있게 설정 |

임대가 만료된 이전 프로세스가 계속 실행되면 외부 AI 호출 자체는 재실행될 수 있다. DB 완료 토큰과 결과 저장 검사는 오래된 완료 및 스냅샷을 막는다. 외부 서비스 자체의 과금 멱등성이 필요하다면 별도의 요청 키 계약이 필요하다.

운영에서는 FAILED 건수, 가장 오래된 PENDING의 대기 시간, RUNNING 임대 만료 빈도를 확인한다. `last_error`에는 예외 클래스명만 기록하며 외부 응답 본문·키는 저장하지 않는다. 과거 잘못 귀속된 센서 행은 자동으로 수정하지 않는다.

## 검증

`SensorReadingServiceTest`, `CareDiagnosisWorkerTest`와 실제 MariaDB의 `SensorPipelineMariaDbIntegrationTest`가 배치 중복·충돌, 동시 재전송, 과거 연결 귀속, 마이크로초 재전송, 활성 연결 제약, 작업 병합·재시도·임대 토큰, AI 장애 후 센서 보존을 검증한다. DB 실행법은 [테스트 문서](testing.md)를 참고한다. 동시성 검증은 실제 커밋된 전용 테스트 데이터를 사용하고 각 테스트 종료 시 정리한다.
